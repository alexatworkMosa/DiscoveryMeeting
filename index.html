פגישת Discovery
אוטומציה לבדיקות תוכנה

03.05.2026
משתתפים בפגישה — מיכל גרינפדל, אסתר מורשת, לאה גולדשטוף, איתי אגמון, אלכסנדר שטיין, אולג קודינסקי
1
נושאים שנדונו
בחירת Stack טכנולוגי לאוטומציה
  • נדונו שפות: TypeScript ו-Python, כל אחת עם יתרונות וחסרונות
  • Playwright זוהה ככלי מועדף לבדיקות UI שילוב מצוין עם VS Code
  • Stack סופי יוחלט לאחר Discovery טכני של הסביבה הקיימת
סוגי בדיקות UI, API ו-End-to-End
  • הובהר ההבדל: בדיקות UI (ולידציות שדות) לעומת end-to-end תהליכיות
  • ה-MVP ישלב שימוש ב-API להכנת סביבה ומשאבים, ובדיקת תהליך מעל ה-UI
  • תרחיש MVP: פנייה מסגרות קטינים מ-Service הרשויות (API) ועד ל-UI המערכת
  • התשתית תאפשר גם UI מפורט וגם end-to-end לפי הצורך
כלי דיווח תוצאות בדיקות
  • Report Portal: חקירת כשלונות, קטלוג סיבות (Bug / Automation / Environment), דשבורדים
  • אלטרנטיבות: Allure Report, Extent Reports, שילוב ב-TFS / Azure DevOps
  • ההחלטה הסופית תיעשה בשיתוף האגף לאחר הצגה והשוואה
סביבת עבודה ונתוני בדיקה (Test Data)
  • הוחלט: האוטומציה תרוץ על סביבת QA לא DEV ולא Production
  • אתגר מרכזי: ניהול Test Data אוכלוסיות קטינים, ת"ז, rollback, נתונים נקיים
  • גמישות ב-database (מחיקה, עריכה, rollback) רצויה ככל האפשר
  • WCF: WSDL מאפשר יצירת client אוטומטית; REST: יש לספק Swagger
  • הספק הדגיש: Test Data הוא האתגר הכי קריטי בפרויקט
שילוב AI בתהליך הפיתוח
  • הספק יוכל להשתמש ב-Kiro (IDE מבוסס AI) + Claude Opus 4.6 לבניית תשתיות
  • AI חוסך כ-80% מזמן כתיבת תשתיות נמצא אפקטיבי מאוד בפועל
  • תסריטי הבדיקה הקיימים ישמשו כ-template ל-AI לכתיבת טסטים אוטומטיים
  • נדרש אדם עם יכולות coding לביקורת ותחזוקת תוצרי ה-AI
מודל משאבים, אחזקה וחזון ארגוני
  • ה-MVP יבוצע על ידי הספק; בהמשך נדרש בעל תפקיד coding בתוך האגף
  • כל שינוי בפיתוח מחייב עדכון אוטומציה מקביל עבודה שוטפת, לא חד-פעמית
  • ה-MVP הוא "סנונית ראשונה" שתיצור תיאבון ו-commitment ארגוני להרחבה
2
החלטות שהתקבלו
מערכת MVP
  • מערכת ועדות חריגים תהליך פנייה מסגרות קטינים, מ-API הרשויות ועד ל-UI, end-to-end
כלי אוטומציה
  • Playwright ככלי עיקרי לבדיקות UI, בשילוב API לכנת סביבה
  • שפה תוחלט לאחר Discovery טכני
סביבת עבודה
  • האוטומציה תרוץ על סביבת QA בלבד לא DEV
  • נדרשת סביבה נקייה עם Test Data מתאים
שילוב AI
  • Kiro + Claude ישמשו לבניית תשתיות על בסיס Angular client-side code
  • תסריטים קיימים ישמשו כ-template
כלי דיווח
  • ייבחר בשלב הבא Report Portal / Allure / TFS לאחר הצגה והשוואה משותפת
מסירה ראשונה
  • הספק ישלח סיכום כתוב מלא של כל הדרישות (סביבה, גישות, נתונים, רישיונות)

משימות ואחריות
הספק

  • הצגת כלי דיווח והשוואה Report Portal, Allure, TFS המלצה ובחירה
האגף
  • קידום אישורים ומודל התקשרות ימים עד שבועות
האגף
  • הקמת סביבת פיתוח בענן עם Kiro + רישיונות AI + VS Code לאחר אישור עסקי
  • הכנת סביבת QA עם גישה לספק גישה ל-application, database, WCF ו-REST APIs
האגף
  • מתן גישה לקוד מקור Angular נדרש לבניית Page Objects ע"י AI, גישה read-only מספיקה
  • הספקת Swagger / WSDL לכל ה-APIs REST: Swagger; WCF: WSDL

סיכום דרישות הספק טרם תחילת העבודה
מסמך שנשלח על ידי הספק לאחר פגישת ה-Discovery
סביבת פיתוח וכלים
  • סביבת פיתוח בענן — יש להעמיד סביבת פיתוח מתאימה בענן, שתאפשר פיתוח והרצה של בדיקות האוטומציה
  • כלי פיתוח — יש להתקין סביבת פיתוח מתאימה לשפת הפיתוח שתיבחר. בשלב זה ההנחה היא שימוש ב-Visual Studio Code
  • כלי AI — יש להתקין ולהגדיר את כלי Kiro, כולל רישיונות AI מתאימים עבור המשתמשים הרלוונטיים
גישות נדרשות
  • גישה לקוד המקור — נדרשת גישה לקוד המקור של ממשק המשתמש של המוצר, המבוסס Angular
  • גישה לסביבת הבדיקות — נדרשת גישה מלאה לסביבת הבדיקות שבה ירוצו תסריטי האוטומציה
  • גישה לממשקי API — נדרשת גישה ל-Swagger של המערכת, לצורך הבנת הממשקים והפעלת בדיקות API
  • גישה לבסיס הנתונים — נדרשת גישה לבסיס הנתונים של סביבת הבדיקות, לצורך שליפת נתוני בדיקה, אימות תוצאות והרצת שאילתות עזר
נתוני בדיקות ומשתמשים
  • פירוט של תסריטי הבדיקות הרלוונטיים לאוטומציה
  • משתמשים בעלי הרשאות מתאימות להרצת התסריטים
  • אוכלוסיות משתמשים מתאימות — לדוגמה מספרי תעודות זהות של קטינים, או לחלופין שאילתות Database שיאפשרו לשלוף באופן דינמי נתונים מתאימים להרצה
דוחות (אופציונלי)
  • לפלייריט יש פתרון דוחות לוקאלי מובנה
  • ישנה אפשרות להתקין שרת דוחות מסוג Report Portal לריכוז והצגת דוחות אוטומציה
הערה: נדרש שלמשתמש במכונת העבודה תהיה אפשרות להתקין תלויות וכלי פיתוח נוספים לפי הצורך, או לחלופין שיהיה איש קשר טכני זמין לביצוע התקנות ומתן הרשאות. נשמח לוודא שההרשאות, הכלים והגישות הנדרשות יהיו זמינים לפני תחילת העבודה, כדי לאפשר התקדמות יעילה ולצמצם חסמים טכניים.
